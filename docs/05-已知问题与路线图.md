# 05 · 已知问题、限制与路线图

## 当前限制（v1 目标：REPL 可用）

1. **无图形设备**：X11/cairo 已禁用。可用 `png()` 出位图后用 ArkUI Image 显示（二期做
   "plots" 页签）；SVG 可考虑 ArkWeb 渲染。cairo 全家桶（freetype/fontconfig/pixman）交叉
   编译量大，放二期。
2. **无中文排序/转写**：未启用 ICU（sysroot 有 libicu.so 缺头文件）。二期把 ICU 头文件
   补齐链接 `libicu.so`。
3. **GBK 等非 UTF-8 编码缺失**：musl 内置 iconv 只覆盖基本字符集。中文用户读 GBK 数据
   会失败，二期引入 `libiconv` 全量字符集。
4. **CRAN 含编译代码的包装不上**：设备上没有 make/gcc。纯 R 包（绝大多数现代包的 R 部分）
   可直接 `install.packages`；编译包需要自建 "OHOS 二进制仓库"（用本工程工具链批量预编译，
   参照 Termux r-cran- 预编译集与 CRAN binary repo 的结构）。
5. **包管理体验**：`Rprofile.site` 已把镜像指向清华 CRAN；`download.file` 的 https 需要
   `BUILD_NET=1`（openssl+curl）。

## 沙箱 noexec 风险（形态 B 的最大不确定项）

- 若鸿蒙沙箱允许 exec/dlopen（OpenHarmony 标准系统历史上未强制 W^X）：方案 A 直接可用
- 若禁止：切方案 B——`R`、`libR.so`、所有包内 `.so` 全部放进 HAP 的
  `libs/arm64-v8a/`（系统保证可执行），R_HOME 数据留在沙箱，包目录里的 .so 用符号链接
  指回 nativeLibraryDir。`40-pack.sh` 已预拷 `librbin.so/libR.so`
- 判定方法见 docs/04 的验证命令

## 性能与体积

- 内置参考 BLAS 慢；二期交叉编译 OpenBLAS（pure C 编译，无 Fortran 障碍，`USE_THREAD`），
  configure `--with-blas="-lopenblas"`
- tar 未压缩约 100–200 MB；二期改 gzip/zip + native inflate，或按需下载
- strip + 去 doc/man/tests 后实测记录体积

## 路线图

| 阶段 | 内容 |
|------|------|
| M1（本仓库） | 交叉编译链 + REPL（hdc 直跑 + HAP 终端页） |
| M2 | png 图形页签、OpenBLAS、ICU、libiconv、gzip 压缩包 |
