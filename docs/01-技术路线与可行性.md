# 01 · 技术路线与可行性

## 目标平台

鸿蒙电脑（MateBook Pro / MateBook Fold 等，HarmonyOS 5.1+ PC，麒麟 X90）本质是
**aarch64 + OpenHarmony（HarmonyOS NEXT）标准系统 + musl libc**。NDK 目标三元组：
`aarch64-unknown-linux-ohos`（sysroot 库目录名为 `aarch64-linux-ohos`）。
x86_64-unknown-linux-ohos 仅用于开源鸿蒙 PC/模拟器，脚本里已留 `OHOS_ARCH` 开关。

## 五个关键问题与对策

### 1. 工具链：OHOS NDK 是 clang + musl，没有 gcc/gfortran

DevEco Studio 自带 NDK（本机在
`D:\Program Files\Huawei\DevEco Studio\sdk\default\openharmony\native`）：

- `llvm/bin/clang --target=aarch64-unknown-linux-ohos --sysroot=native/sysroot`
- sysroot 自带 `libz.so + zlib.h`、`iconv`（musl 内置）、`libicu.so`（无头文件，二期再利用）
- **没有 Fortran 编译器** → 见问题 2

WSL 里交叉编译需要 **Linux 版** OHOS SDK（Windows 版的 clang 是 .exe），获取方式见 docs/02。

### 2. Fortran：用 f2c 转换成 C

R 的 Fortran 代码集中在 BLAS/LAPACK 子集与 `src/appl`，全部是固定格式、实数运算，
f2c 可完整转换。R 源码官方自带示例包装脚本 `scripts/f77_f2c`（R-admin 附录 B.6 "Using Fortran"
明确写明无 Fortran 编译器时可用 f2c 经脚本替代）。

本工程做法：`build/f77` 伪装一个 `F77`——把每个 `.f` 用 f2c 转 C、再用 OHOS clang 编译，
链接时追加交叉编译的 `libf2c.a`（netlib 源码，纯 C）。Termux 的 Android R 移植用的同一路线。

### 3. R 官方"不支持交叉编译"

R-admin 原话 "Cross-building is not possible"：因为 `make` 过程要运行刚编译出的 R 执行
大量构建脚本。对策（Termux 验证过的模式）：

1. 先在 WSL 编译一份 **host R**（x86_64 Linux，`build/00-host-r.sh`）
2. 交叉构建目标 R 时，把构建树里的 `bin/R`、`bin/Rscript` 替换为指向 host R 的包装脚本
3. 配置阶段无法运行的探测用 `config.site` 缓存变量固化（`build/config.site.ohos`）

### 4. 依赖库矩阵

| 库 | 来源 | 说明 |
|----|------|------|
| zlib、iconv | sysroot 自带 | 直接链接 |
| pcre2、bzip2、xz、libpng、libjpeg | `build/10-deps.sh` 交叉编译 | R 必需/推荐 |
| ncurses + readline | `build/10-deps.sh` | REPL 行编辑；静态库 |
| libcurl + openssl | 可选（`BUILD_NET=1`） | 无它则 https 下载不可用 |
| ICU | 二期 | sysroot 有 libicu.so 但无头文件；先不启用，中文排序降级 |
| X11 / Tcl-Tk / cairo | 禁用 | PC 版无 X11；绘图先走 png 位图设备 |

### 5. 怎么"落地"给用户

- **形态 A（开发/极客）**：hdc 推 tar 到 `/data/local/tmp` 直接跑（脚本 `50-install-device.sh`）
- **形态 B（正式产品）**：HAP 应用——ArkUI 终端界面 + NDK 原生桥 `rhost.cpp`
  fork/exec 沙箱内的 R，stdio 走管道；R 安装树打包进 rawfile 首启解压

## 架构（形态 B）

```
Index.ets (ArkUI 终端页)
   │ ①首启: rawfile/rhome.tar → 沙箱 files/ 解包 (native UnpackTar)
   │ ②StartR: nativeLibDir/librbin.so fork+exec, R_HOME=沙箱
   ▼
rhost.cpp (napi 桥) ── stdin/stdout 管道 ──→ R --slave --interactive (libR.so)
   ▲ threadsafe function 回调输出行
```
